# Section 3.2 Federated Environment and Data Construction (English)

This section specifies how the federated learning **environment** is instantiated at the data layer: what enters the communication protocol, how statistical heterogeneity is **synthesised**, and how a server-side **proxy subset** is carved out of the training pool. The description follows the reference implementation in `dataset/data_utils.py`. **Optimization, aggregation weights, and model objectives are out of scope**; only indexing, transforms, and partitioning logic are discussed. Background material on particular public benchmarks is deferred to the experimental chapter.

---

## 3.2.1 System view: who sees which data

From a system-modelling perspective, the training corpus is represented as a finite ordered set of examples \(\{(\mathbf{x}_i, y_i)\}_{i=0}^{N_{\mathrm{train}}-1}\) with global indices \(i\) shared by all logical components. The implementation wraps this corpus in a single `Dataset` object. Three derived objects are materialised before the federated loop begins: (i) a **held-out test** split used only for evaluation (not partitioned across clients in the reference code); (ii) a **server-side proxy** subset \(\mathcal{D}_p\), implemented as a `Subset` over a fixed list of global indices; and (iii) for each client \(k\in\{1,\ldots,K\}\), a list of global indices \(\mathcal{C}_k\) used to build `Subset(train, \mathcal{C}_k)` for local training. Thus, the federated environment is fully specified by the tuple \((\{\mathcal{C}_k\}_{k=1}^K,\ \mathcal{I}_p)\), where \(\mathcal{I}_p\) denotes the index set underlying \(\mathcal{D}_p\), together with the transform applied whenever a tensor is read from disk.

---

## 3.2.2 Preprocessing pipeline: tensorisation and normalisation

The preprocessing pipeline is implemented as a **deterministic** composition of two operators—no stochastic augmentation is applied in the reference code, which keeps the “data construction” story aligned with reproducible benchmarking.

**Tensorisation.** The first stage maps each raw stored example into a floating-point tensor \(\mathbf{x}\in\mathbb{R}^{C\times H\times W}\). Pixel intensities are linearly rescaled from \([0,255]\) to \([0,1]\) and the layout is fixed to channel-first, as required by downstream convolutional modules.

**Per-channel normalisation.** The second stage applies an affine normalisation independently along each channel \(c\in\{1,\ldots,C\}\):
\[
\tilde{x}_{c,h,w} = \frac{x_{c,h,w}-\mu_c}{\sigma_c},
\]
where \((\mu_c,\sigma_c)\) are fixed constants bundled with the codebase for each supported input modality. The same composition is attached to the training split, the proxy `Subset`, and the evaluation split, so that clients, the server proxy loader, and the central evaluator observe **identical** normalisation statistics. Any extension (e.g., random cropping or flipping) would amount to inserting additional `transform` nodes; the current implementation deliberately omits them so that heterogeneity enters **only** through the index partition, not through stochastic views of the same index.

## 3.2.3 Quantifying Non-IID: Dirichlet and pathological partitions

Non-IID structure is injected **purely at the index level** by assigning disjoint subsets \(\mathcal{C}_k\) of \(\{0,\ldots,N_{\mathrm{train}}-1\}\) to clients. Two mechanisms are supported.

### Dirichlet quantity split (class-conditional proportions)

For each class label \(\ell\in\{0,\ldots,L-1\}\), let \(\mathcal{I}_\ell=\{i: y_i=\ell\}\) be the set of global indices carrying that label. The algorithm copies \(\mathcal{I}_\ell\) into a working array, applies a class-internal pseudo-random permutation, draws a **symmetric Dirichlet** vector
\[
\mathbf{p}^{(\ell)} \sim \mathrm{Dirichlet}(\beta,\beta,\ldots,\beta)\in\mathbb{R}^K,
\]
and converts \(\mathbf{p}^{(\ell)}\) into integer split points by cumulative scaling:
\[
s_j^{(\ell)} = \left\lfloor \Big(\sum_{r=1}^{j} p_r^{(\ell)}\Big)\, |\mathcal{I}_\ell| \right\rfloor,\quad j=1,\ldots,K-1,
\]
then partitions the permuted class list at \(\{s_j^{(\ell)}\}\). The segment assigned to client \(k\) is appended to \(\mathcal{C}_k\). Repeating over all \(\ell\) yields \(\mathcal{C}_k\cap\mathcal{C}_{k'}=\emptyset\) for \(k\neq k'\) and \(\bigcup_k \mathcal{C}_k\) equal to the union of all class index sets that participate in the split.

The scalar \(\beta>0\) **quantifies** how balanced class-conditional allocations are: \(\beta\to\infty\) drives \(\mathbf{p}^{(\ell)}\) toward the uniform vector \((1/K,\ldots,1/K)\), approaching an IID-like balance across clients for that class; small \(\beta\) produces highly skewed \(\mathbf{p}^{(\ell)}\), concentrating most samples of class \(\ell\) on a few clients. Thus \(\beta\) is the tunable knob that maps directly to a **numerical heterogeneity level** in the Dirichlet mode.

### Pathological (label-skew) partition

The pathological scheme models **covariate shift via label-support disjointness**. A pseudo-random permutation \(\pi\) of the label set \(\{0,\ldots,L-1\}\) is drawn from a stream keyed by an integer `seed` (implemented as `numpy.random.RandomState(seed)`). The permuted labels are split into \(K\) contiguous blocks (as equal in size as possible). Client \(k\) receives the union of all training indices whose labels fall in the label subset assigned to block \(k\):
\[
\mathcal{C}_k = \bigcup_{\ell\in \mathrm{Block}_k} \mathcal{I}_\ell.
\]
Different clients therefore observe **disjoint sets of classes** (when \(K\le L\) in the intended configuration), which is an extreme form of Non-IID: the marginal label distribution has disjoint support across clients. The degree of “extremeness” is controlled less by a single continuous scalar than by \((K,L)\) and the realisation of \(\pi\); repeating experiments with the same `seed` reproduces the same class-to-client assignment.

### Empty-class guard

If, after optional index removals (see proxy construction), some class \(\ell\) has \(|\mathcal{I}_\ell|=0\), that class is skipped in the Dirichlet loop. This prevents degenerate Dirichlet draws on empty support and keeps the implementation stable for edge cases.

## 3.2.4 Proxy subset: construction and index-level exclusivity

Let \(\rho\in(0,1)\) denote the configured ratio `proxy_ratio`. The target number of proxy examples is
\[
N_p = \mathrm{clip}\Bigl(\lfloor \rho N_{\mathrm{train}} \rfloor,\ 1,\ N_{\mathrm{train}}-1\Bigr),
\]
so that both the proxy subset and its complement remain non-empty.

Two construction modes are available.

**Mode A (legacy, independent draws).** A `torch.utils.data.random_split` is applied to the full training `Dataset` with an optional `torch.Generator` seeded by `seed`. The first fragment of length \(N_p\) becomes the proxy `Subset`. Client partitions are built **before** this split from the **full** index sets \(\mathcal{I}_\ell\). In this mode, \(\mathcal{I}_p\) is not guaranteed to be disjoint from \(\bigcup_k \mathcal{C}_k\); the same global index may appear both in the server proxy loader and in a client’s local `Subset`.

**Mode B (index mutual exclusivity, recommended for the thesis statement).** When `proxy_disjoint_from_clients=True`, the implementation first samples a **uniform random permutation** \(\sigma\) of \(\{0,\ldots,N_{\mathrm{train}}-1\}\) using `torch.randperm` with `Generator.manual_seed(seed)`. The proxy index set is
\[
\mathcal{I}_p = \{\sigma(0),\sigma(1),\ldots,\sigma(N_p-1)\},
\]
and the **residual** mask marks all indices not in \(\mathcal{I}_p\). Class-conditional sets used for Dirichlet or pathological splitting are **restricted** to residual indices:
\[
\mathcal{I}_\ell' = \{ i\in \mathcal{I}_\ell : i\notin \mathcal{I}_p \}.
\]
Clients are then populated from \(\{\mathcal{I}_\ell'\}\) exactly as in Section 3.2.3. Consequently,
\[
\mathcal{I}_p \cap \Big(\bigcup_{k=1}^K \mathcal{C}_k\Big) = \emptyset,
\]
which is the precise **index-level mutual exclusivity** property: no training example used in any client’s stochastic gradient updates in a given run is also used as a labelled proxy batch element for server-side diagnostics derived from the same index space.

**Role of the random seed.** The integer `seed` pins both the proxy permutation (via the PyTorch generator) and, in pathological mode, the label permutation (via NumPy’s `RandomState`). After a global RNG initialisation in the training driver, the Dirichlet draws also become reproducible across runs. The seed therefore does **not** introduce statistical bias by itself; it fixes a single draw from the intended sampling mechanism. “Unbiasedness” in the informal experimental sense should be read as: **no hand-crafted index cherry-picking**—only declared pseudo-random procedures—subject to the chosen \((\beta,K,\rho)\) and partition mode.

## 3.2.5 Interface to the federated execution loop

The function returns `(train_dataset, test_dataset, proxy_dataset, client_id_map)`. The first object is the full training corpus with transforms attached; clients never receive raw tensors from other parties, only their index lists \(\mathcal{C}_k\). The proxy object is consumed exclusively on the server path in the training orchestration. This closes the **data-centric** specification of the federated environment: transforms define the observation space, \((\beta \text{ or pathological } \pi,\ K,\ L)\) define heterogeneity, \((\rho,\ \texttt{proxy\_disjoint\_from\_clients},\ \texttt{seed})\) define the proxy geometry relative to client training support.
